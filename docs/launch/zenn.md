## 「通った」だけでは見えないこと

失敗したテストを直す代わりに skip したり、期待値との一致を存在確認に変えたりすると、実行結果だけでは検証が弱くなったことが見えにくくなります。これは作者がAIか人間かにかかわらず、差分レビューで確認したい点です。特定の製品の動機や発生頻度を、この説明から断定することはできません。

## didit で確認する

![説明用の合成デモ](../../examples/demo/demo.gif)

didit は Git 差分から、スキップ、判定緩和、型・Lint 抑制、設定・CI の緩和などを検出するローカルCLIです。20の差分ルールに加え、任意のテスト実行で失敗・件数減少・スキップ増加を確認できます。JSON、Markdown、次の担当者向けの引き継ぎ資料も出力します。

このデモは小さな Node ハーネスで実際にアサーションを動かす説明用の例です。基準側は3成功、変更後は2成功・1スキップ。Vitest形式の集計を使い、実際の検査結果は high 5件・medium 1件、終了コード1です。実際の利用者の事故例ではありません。

## プレビューの使い方

信頼できるチェックアウトで `npm ci`、`npm run build`、`npm pack` を実行し、調べたいリポジトリに生成された tarball をインストールします。

```sh
npm install --save-dev /absolute/path/to/didit-0.2.0.tgz
npx --no-install didit
npx --no-install didit --run "npm test"
npx --no-install didit init claude
```

`npx didit` はローカル導入済み、または将来の公開先確認後に限る短縮形です。現時点でレジストリから取得しないでください。生成フック・指示・引き継ぎ案内には `npx --no-install didit` を使い、信頼できるローカル導入を必須にしています。繰り返し初期化しても重複しません。[README](../../README.ja.md)に詳しく記載しています。

## 決めつけず、理由を残す

正当なスキップや仕様変更もあります。理由付きの `didit-ok` コメントで解除でき、新しく追加された解除は一覧に残ります。didit 自体の設定変更も指摘します。

静的検査は通信・LLMを使いません。ただしインストールや任意の実行コマンドは通信でき、実行はサンドボックスではありません。文字列ベースの判定には誤検出と見逃しがあります。指摘なしは正しさの保証ではありません。
